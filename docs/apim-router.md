# Model router behind Azure API Management

![APIM router architecture](apim-architecture.png)

Editable source: [`apim-architecture.drawio`](apim-architecture.drawio) (generated by `make_apim_diagram.py`).

Goal: clients call **one** APIM endpoint using the normal Azure OpenAI chat-completions contract. APIM asks the router which model to use and forwards the request to that deployment. The client never has to choose a model.

```
client ──► APIM /openai/deployments/auto/chat/completions
             │ inbound policy
             ├─► send-request → Router API (/api/router/route)   ~0.3 s, cached by prompt hash
             │      returns {choice: small|strong|code, confidence}
             ├─► set-backend-service → AOAI backend pool for that choice
             │      (conf < threshold → strong)
             ├─► rewrite-uri → /deployments/{chosen}/chat/completions
             ▼
          Azure OpenAI / Foundry deployments (nano · 5.4 · codex)
             │ outbound
             └─► set-header x-routed-model, x-route-confidence; emit-metric per model
```

## Policy sketch

```xml
<inbound>
  <base />
  <set-variable name="prompt" value="@(((JObject)context.Request.Body.As<JObject>(preserveContent:true))["messages"].Last["content"].ToString())" />
  <cache-lookup-value key="@("route-" + context.Variables.GetValueOrDefault<string>("prompt").GetHashCode())" variable-name="route" />
  <choose><when condition="@(!context.Variables.ContainsKey("route"))">
    <send-request mode="new" response-variable-name="r" timeout="2" ignore-error="true">
      <set-url>{{router-url}}/api/router/route</set-url>
      <set-method>POST</set-method>
      <set-header name="x-jev-key" exists-action="override"><value>{{jev-key}}</value></set-header>
      <set-body>@(new JObject(new JProperty("prompts", new JArray(context.Variables["prompt"]))).ToString())</set-body>
    </send-request>
    <set-variable name="route" value="@{ var r=(IResponse)context.Variables["r"]; if(r==null||r.StatusCode!=200) return "strong";
        var x=r.Body.As<JObject>()["results"][0]; return (double)x["confidence"] < 0.6 ? "strong" : (string)x["choice"]; }" />
    <cache-store-value key="@("route-" + context.Variables.GetValueOrDefault<string>("prompt").GetHashCode())" value="@((string)context.Variables["route"])" duration="300" />
  </when></choose>
  <set-backend-service backend-id="@("aoai-" + (string)context.Variables["route"])" />
  <rewrite-uri template="@("/openai/deployments/" + (string)context.Variables["route"] + "/chat/completions")" copy-unmatched-params="true" />
  <authentication-managed-identity resource="https://cognitiveservices.azure.com" />
</inbound>
```

## Design notes

- **Fail-safe:** if the router errors or times out, the request goes to the strong model, so quality never degrades silently.
- **Keys:** the Jev key or router secret is held in an APIM named value backed by Key Vault. Clients never see it.
- **Self-hosted option:** point `router-url` at an open-source classifier on a CPU VM or Container App in the same VNet. There's no third-party call, and the data stays in the tenant.
- **Observability:** use `emit-metric` / `llm-emit-token-metric` dimensioned by `routed-model` to prove savings per team. Add the `llm-token-limit` policy per subscription.
- **Streaming:** routing happens before forwarding, so SSE passes through untouched.

## Live proof (2026-09-29, TEAM subscription, Southeast Asia)

Gateway: `https://<your-apim>.azure-api.net/openai/deployments/auto/chat/completions` (APIM subscription key, header `api-key`).

What is deployed (reproduce with `infra/apim/deploy.sh`; the policy is `infra/apim/policy-auto.xml`):

| Piece | How |
|---|---|
| APIM | Consumption tier, system-assigned managed identity |
| Routing | `send-request` to `/api/router/route`, 3 s timeout; strong on timeout, non-200, parse error or confidence < 0.6 |
| Backends | `aoai-small/strong/code` with a circuit breaker (3× 429/5xx in 1 min, trip 1 min, honours Retry-After) |
| Pools | `pool-small` = nano, then 5.4 at priority 2 · `pool-strong` = 5.4 · `pool-code` = codex |
| Auth to AOAI | `authentication-managed-identity`, with Cognitive Services OpenAI User on the AOAI account |
| Jev key | APIM named value backed by Key Vault secret `jev-key` (MI has Key Vault Secrets User) |
| Metrics | `llm-emit-token-metric` with `routed-model` and `route-source` dimensions to Application Insights |
| Response headers | `x-routed-model`, `x-route-source`, `x-route-confidence` |

What the live tier forced (errors are verbatim from the APIM management API):

- `llm-token-limit`: *"Policy is not allowed in 'Consumption' sku"*. `rate-limit-by-key` is also refused. Consumption uses plain `rate-limit` (120 calls/min, named value `calls-per-minute`). The token budget is ready in `policy-token-limit.v2.xml` for Basic v2 or Standard v2. Basic v2 was not deployed, because it has a standing monthly fee and nothing else here needs it.
- Semantic cache (`azure-openai-semantic-cache-*`) needs an external Redis Enterprise cache and an embeddings backend, so it is not deployed. It is optional.
- `gpt-5.3-codex` serves only the Responses API: chat completions returns *"The requested operation is unsupported."*, also when called directly. For the `code` class the policy rewrites chat to `/openai/v1/responses` and maps the reply back to the chat-completion shape. The code pool therefore has no cross-model failover: a trip on codex fails the request instead of silently changing the API shape.
- Expressions cannot use `System.Globalization.CultureInfo`, and `context.Variables` is read-only inside an expression. The policy returns one `class|source|confidence` string and splits it.

### Results: 60-prompt stratified subset of the frozen 240

The subset is 20 per class, split by source using largest remainder, with a deterministic sha256 order. The labels lock was verified. Answers were capped at 32 output tokens, so this measures routing and latency, not answer quality. Four calls were made per prompt: the direct router, APIM `auto`, APIM pinned to the same class, and the Foundry model-router. All 240 calls returned 200.

| | Direct router | APIM `auto` | Foundry `model-router` |
|---|---|---|---|
| Distribution small / strong / code | 27 / 13 / 20 (raw choice) | 20 / 20 / 20 | 7 families (see below) |
| Accuracy vs labels | 51/60 raw, 56/60 with fallback | **58/60** | not comparable (18/60 by a coarse family map) |
| Fallback to strong | – | 13 (all low confidence; 0 timeouts or errors) | – |
| Agreement with the direct router, when the router decided | – | 47/47 | – |
| Latency p50 / p95 | 335 / 625 ms (route only) | 2149 / 3633 ms (route + answer) | 1789 / 2466 ms (answer) |

- **APIM routing overhead** (`auto` minus pinned on the same prompt and class): p50 **125 ms**, p95 1.6 s. The p95 is noisy because both calls include model time.
- The APIM `auto` accuracy differs from the direct-router-with-fallback figure because the two were separate Jev calls: 13 of them came back under 0.6 confidence through APIM. The APIM total is 2 misroutes (1 small→strong, 1 strong→small).
- **Foundry model-router** worked in the same subscription and region within existing quota (`OpenAI.GlobalStandard.ModelRouter` 50 of 1000, version 2025-11-18).
  - It chose gpt-5-mini 21 times, gpt-5.6-luna 20, gpt-5-nano 8, gpt-5 5, gpt-5.6-terra 3, gpt-5.6-sol 2 and gpt-5.4-mini 1.
  - It routes to its own model set, not to our three classes, so "accuracy vs labels" is not meaningful for it. The 18/60 figure maps nano/mini to small, codex to code and everything else to strong, and is shown only for transparency.
  - Token use was the same (4,729 in; 1,920 vs 1,900 out). The per-model prices for its underlying models were not published for this version at the time of the run, so no cost comparison is claimed.
- **Token metrics in App Insights** (`customMetrics`, namespace `jev-apim-router`):
  - Prompt, Completion and Total Tokens are split by `routed-model` × `route-source` (`router`, `fallback-low-confidence`, `pinned`).
  - Example from the run: small/router 20 calls, 1,375 total tokens; strong/fallback-low-confidence 13 calls, 1,471 tokens.

### Cost at idle

About **US$0 per month**. APIM Consumption bills per call, and the first 1M calls a month are free. Key Vault bills per operation, Application Insights and Log Analytics bill per GB ingested, and the model-router deployment bills per token. Under load, add APIM Consumption at about $3.50 per 1M calls, the Jev route call (about $0.023 per 1k routes) and model tokens. Basic v2, which the token-limit policy needs, would add a standing fee; check the current price sheet.
